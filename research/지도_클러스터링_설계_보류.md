## 1. 목표 (영준님 요구)
- 줌아웃하면 개별 마커가 아니라 **묶음 박스**: 검침일 색 + **단상 N / 삼상 M** 개수 (직방 스타일)
- 박스 클릭 → **줌인되며 펼쳐짐**
- 큰 동(창신동 등)은 한 박스로 너무 크니 **지역별로 더 쪼개짐**
- 부가효과: 줌아웃 시 렌더 부하 격감 → 지도 버벅임(J1) 동시 해결

## 2. 확정 설계 = 그리드(격자) 클러스터링
동 고정 카테고리가 아니라 **화면 픽셀 격자 기반**으로 묶는다(직방·네이버부동산 방식).
- 화면을 일정 간격 격자로 분할 → 칸 안의 마커를 묶음
- **줌아웃** → 격자 큼 → 큰 동도 권역처럼 몇 개로
- **줌인** → 격자 작아짐 → 큰 동이 자동으로 여러 박스로 갈라짐, 작은 동은 한 박스
- **검침일 색**: 한 칸에 검침일 섞이면 칸을 검침일그룹별로 분리(복합키 = 격자셀 × 검침일그룹) → 색 명확
- 박스 = 검침일 색(`MARKER_FILL`) + 단상/삼상 개수
- 충분히 줌인 → 개별 마커 펼침
- 클릭 → `map.setZoom(+n)` + `setCenter(clusterPos)` → 기존 idle 재발화로 자연 펼침(별도 애니메이션 불필요)

### 왜 동 카테고리가 아니라 격자인가 (데이터 근거)
- 검침일그룹 G1~G4가 거의 균등 → 검침일만 묶으면 4개 거대 덩어리(의미 없는 centroid)
- 법정동 81개 중 **52개가 검침일 혼재**, 큰 동일수록 심함 → 동 고정으로는 큰 동 처리 불가
- 격자는 줌만으로 큰 동/작은 동을 적응적으로 처리 → 동 경계·개수 무관

## 3. 성능 근거 (이게 J1을 푸는 핵심)
- 현재 마커 = **주소별 집계** `markers=[{overlay, address, meters[]}]`, 고유 주소 **5,636개**
- `refreshAllMarkers()` (js/map.js:828)는 **뷰포트 컬링 없음** → 화면 밖까지 5,636개 전부 생성
- **작업완료 1건마다 5,636개를 전부 setMap(null) 후 재생성** (map.js:837-839) = J1 버벅임의 진짜 원인
- 클러스터 전환 시 줌아웃 = **격자 박스 수십 개**(권역 단위면 최소 8~33개)로 격감 → 약 100~170배 감소
- **주의**: 클러스터를 위에 얹기만 하면 안 줄어듦. 줌아웃 시 개별 마커 `setMap(null)`로 내리고 클러스터만 그려야 함 + 줌인 시에도 `map.getBounds()` 안만 그리는 뷰포트 컬링 필수

## 5. 구현 통합 지점 (재발명 금지)
- 렌더 경로 = `refreshAllMarkers()` (js/map.js:828) + `idle` 리스너(js/map.js:60-63). **여기에 줌 분기로 통합. 별도 zoom_changed 리스너 새로 달면 이중 렌더 레이스.**
- Map 객체 변수 `map`, 줌 = `map.getZoom()`, 마커 배열 `markers`, 전체 데이터 `sampleData`
- 색: `MARKER_FILL`(js/map.js:695-700) + `checkDayClass()`(656) + `decideMarkerStyle()`(528-654). 하드코딩 금지, 그대로 재사용
- **색 모드 토글 확인 필요**: map.html에 `data-mode="checkday"` 활성. status 색 모드(완료=gray 등)도 있으면 클러스터 색도 모드를 따라야 함 — checkday 모드만 검침일색, status 모드면 상태 비율색으로 분기

## 6. 미해결 / 착수 시 결정·튜닝
- **격자 크기**(줌 레벨당 셀 픽셀) — 실제 화면 보며 1~2회 튜닝
