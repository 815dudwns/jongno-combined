## 5. 폐기·교체 절차 (944 → 2576)

> 안전 확인 완료: **944는 2576의 부분집합(고아 0건)**, **기존 명륜 workStatus 0건**. 스왑으로 데이터·완료기록 유실 없음.

### 5.1 백업 (이미 존재 + 추가)
- 롤백 기준선(명륜 0건): `data/jongno-site-data.backup-명륜추가전-20260622-170620.json`
- 교체 직전 현재본도 별도 백업 권장: `data/jongno-site-data.backup-명륜2576교체전-YYYYMMDD-HHMMSS.json`

### 5.2 변환 스크립트 손봐야 할 점 (★중요 — 그냥 재실행하면 깨짐)
변환 스크립트 `scripts/convert_myeongryun.py`는 **옛 944 파일 기준**이라 새 2576에 그대로 쓰면 안 됨:
- **EXCEL 경로(L9)**: 현재 `TalkFile_명륜동19-1019.xlsx`(옛 944) → 새 파일 `~/Downloads/명륜동.xlsx`로 교체.
- **컬럼 인덱스 전부 +1 어긋남**: 옛 파일엔 idx6 "지번/도로명" 병합열이 없어 그 뒤 열이 한 칸씩 밀림. 스크립트는 `C_METER=19`지만 **새 파일 계기번호는 idx 18**. 위 2장 컬럼표(idx) 기준으로 C_RANK·C_CUST·C_NAME·C_JIBUN·C_METER·C_DAY·C_POWER·C_SUPPLY·C_GYEYAK 등 **모든 C_* 인덱스 재매핑 필수**. (검증: 새 파일 순위=1, 고객번호=2, 지번주소=4, 계기번호=18)
- **동그룹 값**: 스크립트 리터럴은 `'명륜동'`이지만, 현 site-data·변환본 944의 동그룹은 모두 **`'명륜'`**(필터가 이걸로 동작). 출력 시 `'명륜'`으로 맞춰야 함.
- 계기타입/단상삼상은 계기번호 3~4자리에서 직접 파싱(스크립트 parse_type/phase 로직 유지, CLAUDE.md 규칙과 동일).

### 5.3 절차
1. 위 5.2대로 `scripts/convert_myeongryun.py` 수정 → 실행 → `data/myeongryun-converted.json`(2,576건, 좌표 포함) 재생성. 카카오 좌표 폴백(도로명→키워드→동중심) 그대로.

4. **★ `python3 scripts/gen_jongno_site_version.py` 재실행** → `data/jongno-site-data.version.json` sha256 갱신. (안 하면 작업자 폰이 옛 IndexedDB 캐시 계속 사용. map.js L209가 이 버전으로 캐시 무효화 판단, L269가 `./data/jongno-site-data.json` 로드)

## 6. '중구작업' 완료마킹 방안과 도구

> 순서 의존: **2576 삽입 → version 재생성(5장 1~4단계) → 그 다음 163 마킹**. 마킹 도구가 awms↔site-data 매칭이라 2576 레코드가 먼저 존재해야 함.

### 6.1 마킹 도구
- `tools/sync-meter-from-awms.html` — **계기번호 매칭**(awms WHM_NO ↔ 종로 계기번호). 163/163 일치하므로 이 도구가 적합.
- `tools/ami-auto-complete.html` — 주소 매칭(보조). 주소도 163/163.

### 6.2 status 구조 제약
- 종로맵 workStatus는 **주소키 기반**. meter_state/comm_state ∈ pending / complete / hold / fail. **'중구작업'·'준공' 같은 특수 state 값은 없음**.
- 163건은 계기교체 완료분이므로 `meter_state='complete'`로 마킹.

### 6.3 '중구작업' 라벨 두 방안 (택1, 영준님 결정 필요)
| 방안 | 내용 | 장단점 |
|---|---|---|
| (가) 라벨만 | `meter_state='complete'` + `meter_updatedByName='중구작업'` | 코드 무변경. 단, 마커색은 일반 완료(회색)과 동일 — 구별 안 됨 |
| (나) 새 state+색 | 새 상태값 추가 + 전용 마커색 | 지도에서 중구작업분을 색으로 구별 가능. 단, map.js·범례·필터 코드수정 필요 |

## 7. 미결정 / 확인필요 사항

1. **데이터 교체 승인**: 944 폐기 → 2576 교체를 진행할지. (안전성은 확인됨: 부분집합·workStatus 0)
2. **중구작업 라벨 방식**: 6.3 (가) 라벨만 vs (나) 새 색. 지도 구별 필요 여부.
3. **과년도 69건 차수배분**: "순위=과년도" 69건을 별도 차수/우선순위로 다룰지. 4개 가에 분산(1가22/2가5/3가29/4가13). 명륜4가 69건과 숫자만 같을 뿐 별개(4가 중 과년도는 13건뿐).
4. **변환 스크립트 수정 주체**: 5.2 재매핑을 누가 적용할지(현재 스크립트 그대로 돌리면 깨짐).
5. **awms 163 완료마킹 시점**: 데이터 교체와 동시 진행 vs 분리.
6. **공급방식 컬럼 중복(idx16·17 둘 다 '공급방식')**: 변환 시 어느 열을 쓸지 확인(스크립트는 C_SUPPLY 단일 가정).
